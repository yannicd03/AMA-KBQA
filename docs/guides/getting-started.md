# Getting Started

Installation and usage guide for AMA KBQA. For a high-level overview of the
project, see the [README](../../README.md).

## Prerequisites

- Python 3.12+
- Docker (Desktop or Engine) installed and running
- An LLM API key (e.g. OpenRouter)

## 1. Install Dependencies

```bash
# Clone the repository
git clone https://github.com/yannicd03/AMA-KBQA.git
cd AMA-KBQA

# Install in editable mode (uv recommended, pip also works)
uv pip install -e .
# or: pip install -e .
```

## 2. Configure API Keys

Copy `.env_example` to `.env` and fill in your API keys:

```bash
cp .env_example .env
```

Review `config.toml` for LLM provider and database settings.

## 3. Start Docker Services

```bash
docker compose up -d
```

This starts **Virtuoso** (SPARQL endpoint, port 8890) and **Qdrant** (vector DB,
port 6333). The compose stack also builds and runs the Streamlit **frontend**
container on port 8502 (see [Usage](#usage)).

## 4. Set Up Datasets

> **Quick setup:** To skip manual data processing, download the pre-built
> datasets and Qdrant snapshots from the project
> [Google Drive](https://drive.google.com/drive/folders/1iEYFboH7l9yRa1xOcJgiYSZlu6Mk2Hhj?usp=sharing).
> The Drive contains:
> - `datasets/kqapro/` - `kb.json`, `kb.nt`, `train.json`, `val.json`, `test.json`, `convert_kb_to_nt.py`
> - `datasets/SciQA/` - ORKG RDF dump, HF/Handcrafted/Autogenerated question sets
> - `fewshot-examples/` - Pre-built few-shot examples for both agents
> - `sciqa/` - Pre-built Qdrant snapshot for SciQA vectors
>
> Place the dataset files into `db/datasets/kqapro/` and `db/datasets/sciqa/`,
> then load them into Virtuoso (see below). For Qdrant, restore the snapshots
> instead of running the populate scripts.

For a deeper walkthrough of adding or integrating datasets, see the
[Dataset Integration guide](dataset_integration.md) and the per-dataset notes in
[docs/datasets/](../datasets/).

### KQAPro (Required)

1. **Get the knowledge base:** Download `kb.json` from
   [HuggingFace](https://huggingface.co/datasets/drt/kqa_pro/blob/main/kb.json)
   and place it in `db/datasets/kqapro/kb.json`.
2. **Convert to N-Triples** *(skip if using `kb.nt` from Google Drive):*
   ```bash
   python db/datasets/kqapro/convert_kb_to_nt.py
   ```
3. **Load into Virtuoso:**
   ```bash
   docker exec -i virtuoso_ama_kbqa isql 1111 dba kit_ama_kbqa "EXEC=ld_dir('/usr/share/proj', 'kb.nt', 'http://kqapro.org/kb'); rdf_loader_run(); checkpoint;"
   ```
4. **Populate Qdrant vectors** *(skip if restoring snapshot from Google Drive):*
   ```bash
   python db/populate_kqapro_vectors.py
   ```
5. **Get question datasets:** Download `train.json`, `val.json`, `test.json`
   from [HuggingFace](https://huggingface.co/datasets/drt/kqa_pro/tree/main) and
   place them in `db/datasets/kqapro/`.

### SciQA/ORKG (Optional)

1. Place the ORKG RDF dump in `db/datasets/sciqa/ORKG RDF dump 14.02.2023.nt`.
2. **Load into Virtuoso:**
   ```bash
   docker exec -i virtuoso_ama_kbqa isql 1111 dba kit_ama_kbqa
   ```
   Then in isql:
   ```sql
   ld_dir('/usr/share/proj/sciqa', 'ORKG RDF dump 14.02.2023.nt', 'http://sciqa.org/kg');
   rdf_loader_run();
   checkpoint;
   exit;
   ```
3. **Populate Qdrant vectors** *(skip if restoring snapshot from Google Drive):*
   ```bash
   python db/populate_sciqa_vectors.py
   ```

## 5. Verify Setup

```bash
# Test KQAPro agent
ama-kbqa ask -s kqapro "Who directed Inception?"

# Test SciQA agent (if installed)
ama-kbqa ask -s sciqa "What papers discuss machine learning?"
```

## Usage

### Frontend (Streamlit)

Run the web UI directly on the host:

```bash
ama-kbqa-frontend
```

This launches a multi-page web app with Chat, Batch Processing, Evaluation, and
Settings pages. Extra Streamlit arguments are passed through (e.g.
`ama-kbqa-frontend --server.port 8502`).

Alternatively, the `frontend` service in `docker-compose.yml` runs the same UI
as a container on port 8502. After a config change you can restart just that
service:

```bash
docker compose restart frontend
```

`config.docker.toml` is bind-mounted as `/app/config.toml` for the container;
edit it on the host and restart the frontend to apply changes.

### CLI

```bash
# Ask using the orchestrator (auto-routes to the right agent)
ama-kbqa ask "Who directed Inception?"

# Ask a specific agent directly
ama-kbqa ask -s kqapro "How many films did Christopher Nolan direct?"
ama-kbqa ask -s sciqa "What papers address text classification?"

# Run benchmarking
ama-kbqa benchmark -s kqapro -n 10 --seed 42
ama-kbqa benchmark -s sciqa -n 10 --seed 42 --dataset handcrafted

# Help
ama-kbqa --help
```

#### CLI Reference

| Command | Description |
|---------|-------------|
| `ask` | Ask a question (orchestrator by default, or `-s kqapro`/`sciqa`) |
| `benchmark` | Run benchmarking with configurable sample size, seed, and postprocessing |

| Benchmark Option | Description |
|------------------|-------------|
| `-s, --subagent` | **Required.** `kqapro` or `sciqa` |
| `-n, --n_questions` | Number of questions (default: 10) |
| `--seed` | Random seed (default: 42) |
| `-p, --postprocessing` | `choice`, `sparql`, `llm_judge`, or `simple` (default: `llm_judge`) |
| `-d, --dataset` | SciQA only: `handcrafted` or `auto` (default: `handcrafted`) |

### Multi-Model Benchmarking

```bash
# Preview what would run
python -m ama_kbqa.benchmark_agents --dry-run

# Single model, single agent
python -m ama_kbqa.benchmark_agents --models minimax-m2.1 --agents kqapro --n-questions 3

# Full benchmark with CSV export
python -m ama_kbqa.benchmark_agents --export-csv

# Resume an interrupted benchmark
python -m ama_kbqa.benchmark_agents --resume
```
