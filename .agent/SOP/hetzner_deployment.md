## Overview

This runbook captures the Hetzner VPS deployment performed on 2026-04-20. The server runs the full AMA-KBQA stack (Virtuoso + Qdrant + Streamlit frontend) as Docker containers, SSH-tunnel-only (no public ports). Reproduce this runbook on a fresh server to get back to the same state.

**Server alias:** `hetzner` (configured in `~/.ssh/config` on the developer laptop)
**Repo path on server:** `~/AMAKBQA-main/`

---

## 1. Docker Compose Stack (3 services)

The compose file is at `db/docker-compose.yml`. It runs **three** services:

| Service | Container | Image | Host port(s) |
|---------|-----------|-------|-------------|
| `virtuoso` | `virtuoso_ama_kbqa` | `openlink/virtuoso-opensource-7` | `127.0.0.1:8890` (HTTP), `127.0.0.1:1111` (ISQL) |
| `qdrant` | `qdrant_ama_kbqa` | `qdrant/qdrant` | `127.0.0.1:6335:6333` |
| `frontend` | `frontend_ama_kbqa` | `ama-kbqa-frontend` (built locally) | `network_mode: host` → binds `127.0.0.1:8502` |

All three have `restart: unless-stopped`.

### Qdrant port offset (6333 → 6335)

Qdrant's host port is **6335** (not the default 6333) to avoid collision with the Orca project running on the same VM. The container-side port is still 6333. This is reflected in `config.toml`:

```toml
[database]
qdrant_host = "localhost"
qdrant_port = 6335
```

### All bindings are 127.0.0.1-only

No service is exposed to the public internet. Access is exclusively via SSH tunnel.

### Start / stop

```bash
ssh hetzner
cd ~/AMAKBQA-main/db
docker compose up -d        # start all 3 services
docker compose down         # stop (data volumes preserved)
docker compose ps           # check status
docker compose logs -f frontend   # tail frontend logs
```

## 2. Frontend Container

The frontend is built from `Dockerfile.frontend` in the repo root:

- Base image: `ghcr.io/astral-sh/uv:python3.12-bookworm-slim`
- Uses `uv sync` for dependency installation (no pip)
- `network_mode: host` — allows the container to reach `localhost:6335` (Qdrant) and `localhost:8890` (Virtuoso) without altering `config.toml`
- `config.toml` is bind-mounted **read-only** at `/app/config.toml` — edit the host file and `docker compose restart frontend` to apply changes
- Healthcheck polls `http://127.0.0.1:8502/_stcore/health` every 30 s

**To rebuild after source changes:**

```bash
ssh hetzner "cd ~/AMAKBQA-main/db && docker compose build frontend && docker compose up -d frontend"
```

**Access on your laptop:**

The SSH config on the developer laptop has:
```
LocalForward 8502 localhost:8502
```
So after `ssh hetzner`, open `http://localhost:8502` in the browser.

## 4. Data Bootstrap

### 4a. Datasets on disk

Datasets extracted to:
- `db/datasets/kqapro/` — `kb.json`, `kb.nt`, `train.json`, `val.json`, `test.json`, `fewshot-examples/`, `convert_kb_to_nt.py`
- `db/datasets/SciQA/` — `ORKG RDF dump 14.02.2023.nt`, `Handcrafted/`, `Autogenerated/`, `HF/`

Snapshot archives are kept in `~/qdrant_snapshots/` on the server for re-restore.

### 4b. Restoring Qdrant snapshots

Collections and their sizes (at time of bootstrap):

| Collection | Points |
|-----------|--------|
| `kqapro-entities` | 17,754 |
| `kqapro-relations` | 363 |
| `sciqa-entities` | 171,588 |
| `sciqa-relations` | 8,596 |

Restore via the Qdrant REST API (run from the server):

```bash
# Example: restore kqapro-entities
curl -X POST "http://localhost:6335/collections/kqapro-entities/snapshots/upload" \
  -H "Content-Type: multipart/form-data" \
  -F "snapshot=@/home/yannic/qdrant_snapshots/kqapro-entities.snapshot"

# Repeat for each collection: kqapro-relations, sciqa-entities, sciqa-relations
```

Verify after restore:

```bash
curl http://localhost:6335/collections | python3 -m json.tool
```

### 4c. Loading RDF into Virtuoso

**KQAPro (graph `http://kqapro.org/kb`, 1,609,805 triples):**

```bash
docker exec -i virtuoso_ama_kbqa isql 1111 dba kit_ama_kbqa \
  "EXEC=ld_dir('/usr/share/proj', 'kb.nt', 'http://kqapro.org/kb'); rdf_loader_run(); checkpoint;"
```

**SciQA/ORKG (graph `http://sciqa.org/kg`, 1,133,217 triples):**

```bash
docker exec -i virtuoso_ama_kbqa isql 1111 dba kit_ama_kbqa
```
Then in the isql prompt:
```sql
ld_dir('/usr/share/proj/sciqa', 'ORKG RDF dump 14.02.2023.nt', 'http://sciqa.org/kg');
rdf_loader_run();
checkpoint;
exit;
```

Verify triple counts:
```bash
docker exec -i virtuoso_ama_kbqa isql 1111 dba kit_ama_kbqa \
  "EXEC=SELECT g, COUNT(*) FROM (SPARQL SELECT ?g (COUNT(*) AS ?c) WHERE { GRAPH ?g { ?s ?p ?o } } GROUP BY ?g) AS sub(g,c);"
```

## 6. LLM Provider Switch

The Hetzner box uses OpenRouter (no local llama.cpp). To switch providers, edit `config.toml` on the server:

```bash
ssh hetzner "nano ~/AMAKBQA-main/config.toml"
# Change [llm] chat_provider and [database] qdrant_port if needed
docker compose restart frontend   # from db/ — picks up new config via volume mount
```

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| Frontend can't reach Qdrant | Port mismatch | Verify `config.toml` has `qdrant_port = 6335` and compose maps `6335:6333` |
| Frontend container won't start | Image not built | Run `docker compose build frontend` from `db/` |
| Config changes not picked up | Container still using old in-memory config | `docker compose restart frontend` |
| Virtuoso RDF load hangs | Background loader still running | Check with `rdf_loader_status()` in isql; wait or cancel and re-run |
| `Address already in use` SSH warning | Pre-existing tunnel | Pass `-o ClearAllForwardings=yes` to ssh or ignore (tunnel still works) |
