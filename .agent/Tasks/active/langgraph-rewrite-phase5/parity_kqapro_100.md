# Phase 5 parity: KQAPro, legacy vs graph engine (2026-08-23)

Both arms from commit `7149256` (code identical to `80ffca9`), same questionnaire
(`kqapro_questionnaire_100_seed42.json`, generated by
`db/generate_question_datasets.py --dataset kqapro --n 100 --seed 42`), same
config: chat + embeddings `openai/gpt-4.1-mini` via OpenRouter (KIT was
unresponsive), judge `deepseek/deepseek-v4-pro`, `reranker_enabled = true`
(`uv sync --extra rerank`), concurrency 4, timeout 300 s. Manifests:
`run_manifest_legacy.json`, `run_manifest_graph.json`. Raw outputs were kept
out of the repo (scratchpad only).

| metric | legacy | graph |
|---|---|---|
| accuracy (LLM judge) | 0.58 | 0.58 |
| errors / timeouts | 0 | 0 |
| prompt tokens per question (mean) | 42,784 | 43,802 (+2.4%) |
| tool calls per question (mean) | 7.07 | 6.90 |
| seconds per question (mean) | 88.1 | 61.8 |

Paired by question: both correct 49, legacy-only 9, graph-only 9, neither 33.
McNemar exact p = 1.0.

Intervention messages found in the final histories (count of questions):

| injection | legacy | graph |
|---|---|---|
| `GetJournalSummary` answer prompt | 24 | 24 |
| wrap-up nudge (iteration ≥ 15) | 4 | 3 |
| periodic journal refresh | 45 | 40 |
| loop-detected tool result | 16 | 22 |
| raw-SPARQL distress / zero-tool retry / compaction / max-iterations | 0 | 0 |

The differences are model-path variance (the same question takes different
trajectories on the two runs; medians of prompt tokens were 41.8k vs 43.7k in
the preceding 20-question pilot). No systematic engine effect is visible.

Cosmetic gap found: the graph engine does not emit the `_trace` log lines
"GetJournalSummary called - injecting answer prompt" and "injecting wrap-up
nudge" although it injects the messages (verified in the histories).

Not covered here: SciQA (ORKG graph only on the Hetzner host) and the
reference KIT model (`kit.gemma4-31b-it`, endpoint down during the run).
Both remain required before the default engine flips.
